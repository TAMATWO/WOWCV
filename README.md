# WOWCV 工作台

Windows / .NET 10 WinForms，使用 OpenCvSharp。提供樣版建立、設定編輯、畫面辨識、原始輸入，以及依技能流程決策與鍵盤施放。

## 使用

主頁採監控工作台布局：頂部固定開始／停止、施放開關與重新定位；左側設定欄可收合並捲動。中央預覽與右側結果可拖曳分隔線調整比例，右側預設顯示「已定位技能」，另保留辨識結果及執行設定暫存。五點明細與底部診斷資訊預設收合，點擊後顯示最新資料；配置警告保持可見，完整警告及來源路徑可由提示查看。布局尺寸與展開狀態不保存。

結果表格採雙緩衝，影格刷新只更新變動儲存格，保留選取項目、捲動位置及自訂欄寬。調整設定仍會清除過期結果，等待新設定的分析；辨識、擷取與施放頻率不受布局調整影響。

1. **建立技能樣版**：載入技能欄截圖，直接在分頁內拖曳框選，設定列數／欄數，從格線預覽確認後匯出 PNG。預設在指定位置建立新的 `Skills_yyMMdd_HHmmss` 子目錄，使用本機時間，例如 `Skills_261025_213045`；同名已存在時依序加上 `_01`、`_02`，不清空或合併既有目錄。當次所有切圖放在同一個資料夾，每張 PNG 使用獨立的 32 位 GUID 檔名（不含連字號）。既有圖片與技能流程綁定不重新命名。
2. **技能流程設定**：新增或刪除按鍵組與技能，設定名稱、狀態、優先序、權重、冷卻秒數及冷卻檢查技能。優先序為整數1～10、權重為整數1～100、冷卻為整數0～600秒，數值直接在表格編輯；超出範圍或小數會就地提示，Esc 可取消。刪除技能直接執行，刪除按鍵組會先確認觸發鍵及技能數量；兩者皆可復原／重做。刪除最後技能保留空組，刪除最後按鍵組保留空文件，不自動修改其他技能的冷卻檢查名稱。提供決策順序／原始順序切換與整組決策順位；顯示排序不改文件原始排列，也不代表固定施放次序。TXT 與 JSON 的內容都是原有 `data / press / process` JSON，保留額外欄位；編輯器刪除不會即時影響主頁已載入的流程。
3. **主頁**：選擇螢幕或靜態圖片，再載入樣版資料夾。可框選 ROI、調整門檻及處理倍率，按「開始偵測」。切換分頁不會停止辨識；停止偵測後保留來源預覽。
4. 主頁「匯入 TXT / JSON 暫存」建立獨立記憶體快照並記住路徑；匯入失敗保留舊內容。編輯分頁的修改／儲存不會即時影響這份快照。要套用修改，請重新匯入已儲存檔案，或下次啟動時由配置記錄的路徑重新載入。

技能流程頁以目前按鍵組的全寬表格直接編輯，技能列約36px；Tab／Enter 提交並移動，Esc 取消當次輸入。名稱、施放鍵、優先序、權重、冷卻、冷卻檢查及 Y／A 狀態可直接修改。Y／A 仍是保留欄位，本階段不影響施放。排序只在提交後更新，並保留目前技能與自訂欄寬。

勾選多個技能後會出現批次工具列：分別啟用要套用的優先序、權重或冷卻欄位，再按「套用選取欄位」。未啟用的欄位及未選取技能不變，一次套用可一次復原／重做。搜尋只篩選目前按鍵組，「全選搜尋結果」只勾選可見列；修改搜尋或切換按鍵組會清除勾選，避免修改隱藏項目。刪除技能會刪除勾選列；未勾選時刪除目前列。新增技能會清除搜尋、顯示新列並開始編輯名稱。

主頁勾選「僅偵測選取區」且已有有效 ROI 時，預覽會等比例放大顯示整個選取區，適用於螢幕與靜態圖片。取消勾選會回到完整畫面並保留選取範圍；再次勾選恢復聚焦。按「框選偵測範圍」暫時顯示完整畫面，完成後聚焦新範圍，再按一次可取消並恢復原範圍。清除範圍或切換來源會回到完整畫面。放大只影響預覽，表格座標與原始 RGB 取樣不變，五點標記依聚焦區域換算顯示；切圖分頁不會自動聚焦。

切圖匯出方式預設「建立新資料夾」。若要把另一張來源圖片的切圖放入同一份樣版資料夾，載入第二張圖片並框選後，改選「加入既有資料夾」，按「匯出 PNG」選擇第一批輸出的資料夾即可。這個模式直接新增 GUID PNG，不另外建立子目錄，也不覆寫或刪除原有檔案。加入模式的資料夾彈窗會優先開啟本次程式執行中上次成功輸出的資料夾；建立新資料夾模式則記住上次選擇的父目錄，此記憶不寫入配置。若主頁已載入該資料夾，新增完成後須重新載入樣版資料夾，才會更新辨識快取。

切圖分頁預設開啟「放大鏡」，倍率為原圖4倍，可調整2～12倍。滑鼠移到圖片上時，游標旁顯示原圖局部像素、十字線與原圖 X／Y；拖曳框選時持續更新，接近預覽邊緣會自動換邊，移到留白或離開圖片時隱藏。十字線使用與框選端點相同的座標換算；放大鏡只輔助看清位置，不改變原本拖曳的座標精度，也不提供整張圖片縮放或鍵盤微調。它不攔截滑鼠、不修改圖片或匯出內容，主頁預設不啟用；開關與倍率只保留於本次執行，不存入配置。

### 技能綁定與記住技能框

1. 在主頁載入樣版資料夾（例如切圖匯出後的資料夾）。流程編輯器的技能列按「選圖」開啟檔案彈窗，預設開啟相同資料夾；選取後顯示檔名，也可按列內「清除」解除綁定。圖片須位於主頁載入的資料夾內。
2. 選取或新增技能，選擇對應圖片，再填「施放按鍵」。例如觸發流程是 `E`，技能圖片是 `Skill_R1_C1.png`，施放鍵是 `1`；也支援 `Ctrl+1`、`Alt+Shift+F2`、`Space`，以及 `-`、`=`、`[`、`]`、反斜線、`;`、單引號、逗號、句點、`/`、反引號等符號鍵。符號鍵代表鍵盤的實體按鍵，不自動加入 Shift；也可與修飾鍵組合，例如 `Ctrl+-`。
3. 儲存技能 TXT／JSON，再從主頁重新匯入。編輯器的修改不會直接修改主頁已載入的流程暫存。
4. 勾選五點驗證並開始偵測。OpenCV 與五點驗證第一次最終命中後，程式以綁定資料確定技能名稱並記住原尺寸框位置。
5. 查看主頁右側「已定位技能」，可見技能、樣版、施放鍵、狀態、點數與座標。選取一筆結果可查看最新五點 RGB；預覽以虛線標示選取的記憶框，符合為綠色、未符合為青色。

已定位後，每份新影格都直接讀取記住位置的五點，不再以當次 OpenCV 候選是否通過作為讀取條件。主頁「辨識結果」仍獨立顯示當次 OpenCV 結果，因此閃爍時可以出現「候選未通過，但已定位技能仍命中」。五點設定為4時，每次仍讀取五點，至少4/5符合就通過；不會改為要求五點全符。`status` 欄位保留在流程中，這階段不區分 Y／A 次數狀態。

「重新偵測」重新分析當前畫面並保留技能位置；**「重新定位技能」**清除位置，等待下一次 OpenCV＋五點通過。已記位置不隨新候選漂移，技能換格或技能欄移動後請重新定位。首次定位時若圖示正受特效或冷卻影響，需要先等一次成功命中。

切換來源、來源尺寸改變、修改 ROI、重新載入樣版資料夾或主頁流程時，會清除位置。門檻、處理倍率、RGB 容差及最低點數變更不清除位置；修改取樣位置時，使用原樣版重新讀取對應 RGB。停止偵測會標示「暫停」，不把舊成功結果當作現在命中；重新開始可沿用位置。關閉五點驗證同樣暫停定位與持續驗證，單純 OpenCV 命中不會建立位置記憶。

位置只存在記憶體，重開程式重新定位，不寫入 `config.json`。靜態圖片僅在設定改變或按「重新偵測」時重新分析；螢幕來源依現有影格持續更新。候選搜尋與記憶框驗證沿用同一條影像執行緒及同一份原始影格，更新速度仍受擷取與分析耗時影響。

技能流程每個技能新增兩個選填欄位，舊檔案缺少時仍可開啟並顯示為未綁定：

```json
{
  "skillname": "魯莽",
  "status": "Y",
  "template_file": "Skill_R1_C1.png",
  "cast_key": "1",
  "priority": 1,
  "skillweight": 100,
  "cd_sec": 0,
  "cooldown_check": ""
}
```

`template_file` 僅保存檔名，由主頁樣版資料夾解析，不接受完整路徑。跨流程的相同綁定共用一個技能框；同一技能綁不同樣版／按鍵，或同一圖片綁不同技能名稱，會提示衝突並略過。缺少名稱、圖片或施放按鍵，以及檔案遺失／無法讀取，都不會猜測綁定或建立定位。切換主頁樣版資料夾不會刪除既有缺失圖片的綁定，仍可修正後再保存。

### 技能決策與施放

編輯器、主頁匯入及啟動恢復共用技能數值驗證：`priority` 1～10、`skillweight` 1～100、`cd_sec` 0～600。原始值越界時拒絕匯入並指出技能／欄位，保留原資料。範圍內的舊小數冷卻會四捨五入（.5向上），例如15.45→15、15.5→16；主頁只轉換暫存並顯示提示，不修改流程原檔。編輯器轉換後標示未儲存，手動儲存才更新檔案，輸出的冷卻不含小數點。其他欄位與額外資料保留。

1. 主頁使用螢幕來源，載入完整樣版及流程，啟用五點驗證後按「開始偵測」。靜態圖片僅供辨識測試。
2. 選擇觸發模式，設定「共用間隔 ms」及「按鍵持續 ms」，再勾選獨立的「啟用技能施放」。此開關不隨配置恢復。
3. 按住模式下，後按的 `press` 生效；放開後恢復仍按住且最近按下的流程。切換模式下，最後按下的流程生效，再按同一鍵停止。鍵盤自動重複不會觸發切換；啟用前已按住的觸發鍵須放開再按。
4. 每輪只從作用中流程依 `priority` 小值、`skillweight` 大值、原排列先後選一個技能。必須五點命中、自身與 `cooldown_check` 指定技能都不在程式冷卻中，才送出 `cast_key` 至目前前景視窗。

按鍵持續時間預設 **30ms**（可設 1～5000ms）；完整按下與放開後才開始計算技能 `cd_sec` 及全體共用間隔。共用間隔預設 **150ms**（可設 0～60000ms），A 施放後 B、C 也須等待。間隔結束且取得「送鍵完成後才開始擷取」的新畫面完整技能驗證，才再次選擇；不能只看分析完成時間，也不能重用送鍵前截圖。間隔為0時仍須等待新畫面。A 若仍命中且冷卻允許，可以再次選中，不要求先變成未命中。

`skillname` 使用去除頭尾空白後的名稱（區分大小寫）共用跨流程冷卻；不同流程施放同名技能會受同一份冷卻限制。此次規則的 `cd_sec` 決定本次到期時間，`cooldown_check` 查同一份紀錄。停止／重新啟用不清除冷卻，關閉程式後不保存。成功送鍵只代表輸入已送出，不代表遊戲已確認施放。

流程觸發鍵目前支援單一鍵盤按鍵；施放鍵支援單鍵及 Ctrl／Alt／Shift 組合。缺少名稱、樣版檔名或施放按鍵的技能會跳過，其他已完成綁定的技能仍可運作；不會自動沿用其他流程同名技能的綁定。若整份流程都沒有完整綁定的技能，則拒絕啟用。重複觸發鍵、完整綁定的無效按鍵／衝突、找不到的冷卻檢查名稱或已綁定樣版檔案遺失仍會阻止啟用，原因顯示在施放狀態列。施放鍵不得包含任何流程觸發鍵。滑鼠輸出不納入此版。

停止偵測、重新設定辨識／來源／ROI、重新定位、重新匯入流程或修改施放參數都會停用施放，需重新勾選；停用施放本身不停止辨識。擷取、辨識、Raw Input 或按鍵輸出發生錯誤時也停用施放。已按下的程式按鍵會嘗試放開，不會放開原本由使用者按住的修飾鍵。底部狀態列顯示作用中流程、最近施放技能及等待／失敗原因。

### 自動保存配置

`config.json` 位於 **EXE 所在資料夾**。在 Visual Studio 執行時，通常位於 `bin/Debug/net10.0-windows/`，主頁底部顯示實際完整路徑。修改設定後約 500 ms 合併保存，正常關閉前也會完成待保存變更。首次沒有檔案時使用預設值，第一次修改後才建立檔案；不會在啟動或尚未修改時覆寫檔案。

| 分類 | 保存內容 |
|---|---|
| `source` | 螢幕識別名稱、`screen`／`image` 來源模式、圖片路徑、樣版資料夾路徑 |
| `search` | 門檻、處理倍率、多尺度、僅偵測選取區、ROI 的座標／尺寸及建立時來源尺寸 |
| `verification` | 五點啟用狀態、五點 X／Y 偏移、RGB 容差、最低點數 |
| `skillFlowPath` | 主頁載入的技能 TXT／JSON 路徑 |
| `casting` | `mode`（`hold`／`toggle`）、`minimumIntervalMs`、`keyHoldMs`；不保存啟用、觸發或冷卻狀態 |

配置格式版本是 `version: 1`；只保存路徑與參數，不包含圖片、流程內容或辨識結果。切回螢幕模式仍保留上次靜態圖片路徑。相對路徑以配置檔所在資料夾為基準。切圖分頁不記憶上次操作，技能流程編輯器不與主頁暫存連動。`Properties` 資料夾維持原樣，不參與這套配置。

啟動時會恢復設定、載入樣版與流程並預覽來源，**不會自動開始偵測**。ROI 僅在來源識別與尺寸符合、範圍有效時恢復；原螢幕不存在、圖片失效或尺寸改變時停用舊 ROI 並提示。圖片無法載入時暫用可用螢幕預覽。失效的圖片、資料夾與流程路徑仍保留在配置，方便修正；其他有效設定照常恢復。

每次保存先寫入 `config.json.tmp` 並完成寫入，再替換正式檔案，上一版保留為 `config.json.bak`。損壞或不支援的配置會提示並使用預設值，啟動時不覆寫原檔；之後修改設定時才保存新版本並備份舊檔。資料夾不可寫入或檔案被占用時，主頁顯示保存失敗，待保存內容保留供後續修改／正常關閉時重試；關閉時仍失敗會另行提示。配置、備份及暫存檔均不納入 Git。

門檻預設 `0.8`，處理倍率預設 `1.00`，多尺度預設關閉。處理倍率小於 1 時，同時縮小 ROI 與樣版以降低搜尋運算量，再在原圖附近以原尺寸精度校正位置；校正範圍隨倍率計算，並限制在 ROI 內。候選框原尺寸由原始樣版及多尺度倍率決定，不從縮小後四捨五入的寬高推算。

每張樣版回報一個最佳候選。OpenCV 的 `1 − SqDiffNormed` 達門檻後，只代表「候選通過」，接著做五點 RGB 驗證，通過才算「最終命中」。黃框表示通過候選但驗證未通過；綠框表示最終命中。表格同時列出未達標候選供診斷；樣版大於整個搜尋區域時略過。MSE 另列，不作命中門檻，在搜尋階段的灰階候選區塊與樣版上計算。

主頁「辨識結果」與「已定位技能」結果表格使用12pt字體，以「縮圖」欄搭配短檔名顯示樣版；已定位技能的縮圖位於技能欄之前。縮圖以字體高度為大小並保留圖片比例，資料列使用緊湊高度；長檔名只顯示前8碼、省略號與副檔名，滑鼠停留在縮圖或檔名上可查看完整檔名。這只改變表格顯示，原始檔名、五點明細與技能綁定仍使用完整名稱。兩個表格共用縮圖快取，重載資料夾時更新，關閉時釋放。

### 五點驗證

- 主頁 **「五點驗證」預設勾選**。取消後，只依 OpenCV 門檻判斷；多尺度維持原有 0.8～1.2 倍搜尋（間隔 0.05）。
- 按主頁左側 **「展開五點設定」**，調整所有技能共用的設定。五個點各自有相對於樣版中心 `(寬/2, 高/2)` 的 X、Y 偏移；預設中心及上下左右各 10 像素，每點都能獨立修改。
- **RGB 容差**可設 `0～255`，預設 `0`。每個取樣點的 R、G、B 都須與樣版對應點相差不超過此數值，該點才通過。
- **最低通過點數**可設 `1～5`，預設 `5`。任一取樣位置越界時，整體拒絕命中，不會偷偷移動取樣點或降低點數要求。
- 五點驗證只讀未縮放、未畫框的原始彩色影像及原始彩色樣版。多尺度候選與樣版尺寸不同時標示「尺寸不符」，不將 RGB 縮放後強行比較；可使用對應尺寸的樣版，或取消五點驗證。
- 選取結果表格的一列，下方顯示五點的樣版位置、畫面位置、預期／實際 RGB 及符合情況；預覽疊加相同編號的取樣標記。這些標記不會寫入取樣資料。畫面位置是該張預覽內的座標；結果表格的中心座標在螢幕模式下包含桌面偏移。
- 五點一致代表取樣特徵一致，無法保證整張圖或完整可施放條件一致。先用零容差、5/5 觀察結果，再依實際畫面調整。

**「匯入／匯出辨識設定」**保存啟用狀態、RGB 容差、最低點數及五點位置，預設檔名 `pixel-verification.json`。它是選用的備份／轉移功能，不修改既有技能流程 TXT／JSON。匯入先驗證完整設定，再一次套用並自動保存進整體 `config.json`；失敗保留原設定。匯出不改變目前設定。處理倍率等其他搜尋設定不包含在這份獨立五點檔案內。

螢幕模式的中心座標包含螢幕桌面偏移，可為負數；靜態圖片使用圖片中心座標。樣版倍率是相對於載入樣版的倍率，不是處理倍率。按「載入樣版資料夾」重選同一路徑可重新載入更新的 PNG。

## 執行緒與服務

| 主要執行緒 | 責任 |
|---|---|
| UI | 分頁、控制項、約每 100 ms 取最新結果及預覽 |
| `WOWCV Capture` | 約每 100 ms 擷取螢幕；靜態來源僅在設定版本變更時讀取 |
| `WOWCV Image` | 彩色／灰階樣版快取、ROI、縮放、多樣版／多尺度、原圖位置校正、五點驗證、MSE |
| `WOWCV Raw Input` | 自有 message-only window 與 STA 訊息迴圈，接收背景鍵盤／滑鼠事件 |
| `WOWCV Casting` | 觸發流程、技能排序、共用間隔、跨流程冷卻及序列化鍵盤輸出 |

共 5 條應用程式主要執行緒；切圖匯出短暫使用執行緒池，.NET／GC 等也可能有自己的執行緒。入口將 OpenCV 運算設定為單執行緒，辨識不另用 `Parallel.ForEach`。

`Services/DetectionPipeline` 在擷取與處理之間只保留一張待處理影格，UI 端也只保留一份待顯示預覽。新影格取代舊影格時立即釋放；設定版本不符的結果捨棄。停止與關閉會取消工作並等待結束，再釋放原生資源。`LatestResults` 提供不依賴 UI 消費的唯讀最新結果，設定變更時清空。

`Services/RawInputService` 管理低階 `IRawInput`／`RawInput`。事件在輸入執行緒觸發，訂閱者須快速返回，不能直接更新控制項；可讀取 `PressedKeys`、`IsPressed` 與 `LatestMouse`。`IRawInput` 仍須在其視窗執行緒使用，其他執行緒應透過包裝服務存取。`WindowsSendInput` 實作 `ISendInput` 的鍵盤部分，標記自身輸出；Raw Input 忽略帶有該標記的事件。測試注入記錄型輸出，不使用真實按鍵輸出。

`RuntimeConfiguration.Read()` 每次回傳獨立文件；呼叫端修改不會污染暫存。`SkillCastingPlan` 編譯流程與鍵盤綁定，`SkillDecisionEngine` 管理純選擇與冷卻，`SkillTriggerState` 處理觸發邊緣；`SkillCastingService` 專用線程協調上述服務。透過 `TimeProvider` 及 `ISendInput` 可獨立驗證時間與輸出。`DetectionPipeline.SkillsUpdated` 發布完整新結果／失效通知，施放服務不依賴 UI 的100ms刷新。

`PixelVerificationOptions` 是不可變的全域設定快照，隨 `DetectionSettings` 交給影像執行緒。`PixelVerificationService` 負責純像素比較；`DetectionRow` 分開提供候選門檻結果、五點結果、最終命中及校正後框位置。每幀先完成所有技能驗證，最後才畫框，避免重疊候選互相污染。

`SkillImageBindings` 建立不解讀 STATUS 的唯讀綁定快照，由 `RuntimeConfiguration.Bindings` 保存版本與資料。`SkillTrackingService` 在影像執行緒管理位置記憶、失效與持續驗證，不持有 Mat，也不送出輸入。`DetectionPipeline.LatestSkills` 發布獨立於 UI 消費的不可變結果，包含設定版本、影格編號、擷取開始的單調時間、UTC 擷取時間、分析完成時間，以及每個技能的五點明細。設定切換與停止時清除已發布的舊結果。所有候選與記憶框取樣完成後，最後才呼叫繪圖。

`WorkbenchConfiguration` 集中定義配置及預設值，`WorkbenchConfigurationStore` 負責驗證、合併寫入、原子替換及備份。啟動批次恢復不觸發保存；背景寫檔使用短暫執行緒池工作，不增加常駐主要執行緒。測試可指定配置路徑，所有驗證皆使用隔離目錄，不會讀寫正式使用的 `config.json`。

## 驗證

```powershell
dotnet build
dotnet run --project Tests/WOWCV.Validation.csproj
```

驗證不需額外測試框架，使用合成影像檢查樣版、多尺度、ROI／負座標還原、原圖位置校正、RGB 容差與點數、設定讀寫、框線污染、MSE、切圖、背景管線、Raw Input 註冊／關閉及分頁建構。產物保留在驗證程式輸出目錄的 `artifacts`，包含各分頁及五點設定離屏繪製的 PNG。

實機驗收：選擇實際螢幕並開始偵測，操作其他分頁和其他視窗確認輸入狀態仍更新；於不同螢幕／DPI 驗證框選及座標，最後關閉程式確認無殘留程序。測試不會模擬鍵盤滑鼠輸入。
